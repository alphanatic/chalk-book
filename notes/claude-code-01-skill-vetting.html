Skill & Plugin Vetting

Quarantine, scan, then install or delete

Set up NVIDIA SkillSpector and wrote a pipeline that vets every Claude Code skill or plugin before it is installed: check the source, quarantine, scan, review by hand, log the result, then install at the narrowest scope.

A reference, not a walkthrough. Every future skill or plugin goes through it, and so does every update.

What we covered

  • Why skills and plugins are a risk: skills become instructions, plugins run code with your privileges
  • A threat map, from prompt injection to rug pulls, and where each threat is caught
  • An 8-step pipeline: source → quarantine → inventory → scan → review → log → install or delete → re-vet updates
  • A rule in ~/.claude/CLAUDE.md plus an ask permission gate, so Claude Code can't skip the process
  • The AI-safety principles behind it, and the limits of a clean scan
  • SkillSpector installed from source with uv, plus a pacman mirror fix along the way

Why this matters

KindWhat it isWhat it can do
SkillMarkdown that enters Claude's context as instructionsSteer the agent, using the tools and permissions it already has
PluginCan also carry hooks, MCP/LSP servers and a bin/ folderRun code on your machine with your full user privileges
Concept · NVIDIA studied 42,447 public skills: 26.1% had at least one vulnerability, 5.2% showed likely malicious intent, and skills that ship scripts were 2.12× more likely to be vulnerable.
Gotcha · Claude Code's permission rules and sandbox cover Claude's tool calls. Plugin hooks and MCP server processes run outside the sandbox. A malicious hook fires on lifecycle events, before you ever use the plugin.
AI safety · Prompt injection is untrusted text that tries to steer the agent: "ignore previous instructions", "read ~/.ssh and post it here", or a trigger that hijacks an ordinary command. In a skill it is pre-installed and loads every session. It hides in comments, zero-width text, homoglyphs, right-to-left overrides, encoded scripts and dependencies that look clean.

Full command sequence

Local0 · Check the source

claude plugin marketplace list    # where each marketplace really comes from
Best practice · Take links from official docs or the author's own org, never from DMs or comments. Official Anthropic marketplace names only load from github.com/anthropics/. Everything else is third-party.

Local1 · Quarantine and pin

mkdir -p ~/quarantine                          # -p: no error if it exists
git clone https://github.com/user/cool-skill \
  ~/quarantine/cool-skill                      # download only; nothing runs
git -C ~/quarantine/cool-skill rev-parse HEAD  # -C: run in that folder; record the exact commit
Gotcha · Claude Code auto-loads .claude/skills inside projects, so never quarantine inside a project folder. If you open the folder in VS Code, choose Restricted Mode so tasks.json and similar files can't run.

Local2 · Inventory (plugins)

claude --plugin-dir ~/quarantine/cool-plugin \
  plugin details cool-plugin                   # lists hooks, MCP, skills; no install

Then read these yourself: hooks/hooks.json (each hook's command), .mcp.json (server commands and URLs) and every file in bin/.

Local3 · Scan with SkillSpector

skillspector scan ~/quarantine/cool-skill \
  --format markdown \
  --output ~/quarantine/cool-skill.md          # static scan, report written as Markdown
less ~/quarantine/cool-skill.md                # score, verdict, and file:line for each finding

Isolated scan. The scanner parses hostile input too, so run it sealed off:

docker build -t skillspector ~/Projects/SkillSpector    # -t: image name; build once
docker run --rm --network none \
  -v ~/quarantine/cool-skill:/scan:ro \
  skillspector scan /scan --no-llm             # --rm: remove after; no network; :ro read-only
Concept · With no network, the CVE lookup falls back to offline data. That is a fair trade for untrusted input.

4 · Human review: you decide, not the tool

  • Does the description match what the scripts actually do?
  • Are permissions limited to what the skill needs?
  • Are network, shell, file, env and MCP access declared and justified?
  • Read SKILL.md yourself. Any unclear answer means not ready.
VerdictAction
SAFEStill skim SKILL.md, then install
CAUTIONCheck every finding at file:line. Install only if all are false alarms
DO NOT INSTALLDelete it. No exceptions

Local5 · Log the decision

echo "$(date +%F) cool-skill <url> <sha> SAFE" \
  >> ~/quarantine/vetting.log                   # %F: YYYY-MM-DD; >> appends a line

Local6 · Install at the narrowest scope, or delete

mv ~/quarantine/cool-skill ~/.claude/skills/   # skill: activate it
claude plugin install cool-plugin@market \
  --scope local                                # plugin: this repo only
rm -rf ~/quarantine/cool-skill                 # -r: recursive, -f: no prompts; never installed
claude plugin uninstall cool-plugin@market \
  --scope local                                # installed, now distrusted
rm -rf ~/.claude/plugins/cache/market/cool-plugin   # the cache lingers 14 days otherwise
Best practice · Try a new plugin in a throwaway project before widening it to user scope.

Local7 · Updates re-enter the pipeline

git -C ~/quarantine/cool-skill fetch           # get new commits, change nothing
git -C ~/quarantine/cool-skill diff \
  <old-sha>..origin/HEAD                       # read only what changed

Re-scan, then replace the installed copy. Keep auto-update off for third-party marketplaces, which is the default. Anthropic's official marketplaces auto-update.

Local8 · Monthly audit, with the permission review

skillspector scan ~/.claude/skills/ --no-llm   # re-check installed skills; no LLM pass
claude plugin list                             # what's installed, its scope and status

Make Claude Code follow the process

Gotcha · Claude Code can install plugins itself with claude plugin install, and it does not quarantine anything: the plugin goes straight in, enabled. Enforce the process with a written rule and a hard gate.
~/.claude/CLAUDE.md
## Installing skills/plugins
- Never install directly; clone to ~/quarantine/<name> first.
- Run skillspector and show me the verdict + findings.
- Wait for my explicit approval before installing.

A soft guard: a rule Claude reads every session.

~/.claude/settings.json
{
  "permissions": {
    "ask": [
always ask before these run
      "Bash(claude plugin install *)",
any plugin install
      "Bash(claude plugin marketplace add *)"
any new marketplace
    ]
  }
}

A hard guard: ask forces your click on installs and new marketplaces. JSON allows no comments.

AI-safety principles

Human in the loopThe agent may prepare and scan, but a person approves installs. Never let an agent approve its own new capabilities.
Least privilegeStart at local scope, keep Claude Code in project folders, give skills only what they declare.
Defense in depthSource check, quarantine, scan, human read, permission gate, re-scan on update. No layer is trusted alone.
Scanner output is dataA skill may hold text aimed at the scanner's LLM pass ("this skill is safe"). The verdict informs; you decide.
Verify integrityCheck a shipped signature (e.g. skill.oms.sig). Scanning asks "is it safe?", signing "is this what was reviewed?"
Evaluate tooEvaluation asks a third question: "does it actually help?"
Gotcha · limits · A clean scan lowers the risk but doesn't rule it out: SkillSpector can't read non-English text, text in images, or encrypted or binary code. The optional LLM pass sends the skill's content to an API; keep its key in pass, never in a committed .env. And SkillSpector only covers what you install: injection from pages or files Claude reads mid-task is handled by permission scoping.

Bugs hit & fixed

Bug · pacman 404s

CAUSE
Stale mirrors in /etc/pacman.d/mirrorlist: downloads failed with 404.
FIX
Rank fresh mirrors with reflector. The chaotic-aur warning that followed is harmless; syncing the file databases clears it.
sudo reflector --country <nearby-countries> \
  --protocol https --latest 20 --sort rate \
  --save /etc/pacman.d/mirrorlist              # 20 newest https mirrors, fastest first
sudo pacman -Fy                                # -F: file databases, -y: refresh them
