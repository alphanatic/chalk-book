Naming Conventions

Cross-cutting reference

Every naming pattern established across the lab so far — AWS resources, admin vs. service accounts, systemd units, and log/config files.

This file is a reference, not a walkthrough — check back here whenever you name something new in later days.

Best practice Paths

Core philosophy

Every name should tell you, at a glance, what it's for and what category it belongs to:

  • type / workload / env / region fields for cloud resources
  • adm- / svc- prefixes instantly separate a human's admin account from a service's unattended account
  • Consistent 1:1 naming between a service and its supporting files (unit file, log folder, logrotate config) so nothing requires memory to trace
Updated rule · Cloud naming moved to the professional pattern <type>-<workload>-<env>-<region>-<instance>, the widely used Microsoft Cloud Adoption Framework style. Patterns 1 and 2 show the old form crossed out. Day 1 resources still carry the old names, e.g. aws-lab-ubuntu-01.

The patterns

  • AWS resources (key pairs, VPCs, subnets, security groups…) <type>-<workload>-<env>-<region>-<instance>
    Type first so resources group in lists; short region codes. Example: kp-ubuntu-lab-eun1-001
    Replaces aws-<env>-<purpose>-<id>
  • EC2 instances vm-<workload>-<env>-<region>-<instance>
    Same rule with type vm. Example: vm-ubuntu-lab-eun1-001
    Replaces <env>-<purpose>-<id>
  • Personal sudo/admin username adm-kiwi
    Dots are invalid in Linux usernames — only letters, digits, _ and -.
  • Service accounts svc-<purpose>
    No login shell, no sudo. Example: svc-disk-report
  • Systemd unit files <purpose>.service
    No extra prefix — location + extension already say what it is. Example: hello-loop.service
  • Log directories /var/log/<service-name>/<service-name>.log
    One dedicated folder per service. Example: /var/log/disk-report/disk-report.log
  • Logrotate config files /etc/logrotate.d/<service-name>
    No extension — matches the .d folder convention. Example: /etc/logrotate.d/disk-report
