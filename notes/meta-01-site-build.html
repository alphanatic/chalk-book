Site & Workflow Build

From a folder of PDFs to a browsable, searchable notebook

Renamed log-book to Chalk Book. Set up a memory-dump skill that works from any folder. Rebuilt the notes as pastel HTML and built a dark static site to browse, search and export them. Pushed it all to a private GitHub repo.

Every later note comes out of this workflow. The rules live in CLAUDE.md, and the guide is a copy of them.

How the site works

index.htmltop bar, left menu, viewer, Recently viewed, main footer
site/notes.jscatalogue: projects, roadmaps, notes
search-index.jsplain text of every note, generated
notes/*.htmlone A4 sheet each, shown in an iframe
Gotcha · When the site is opened from disk (file://), every file counts as its own origin. The site can't fetch data or reach into the note's iframe. So the data is loaded as <script> files, and the site talks to the note with postMessage.

Bugs hit & fixed

Bug · note sheet showed a beige frame instead of dark

CAUSE
With no background on html, the browser spreads the body background (paper) over the whole canvas of the iframe.
FIX
Give html a transparent "image" background, and set color-scheme: dark to match the site (screen only).
notes/note-layout.css
:root { color-scheme: dark; }
html { background: linear-gradient(transparent, transparent); }

Bug · hidden iframe still showing

CAUSE
A display: block rule beat the browser's built-in [hidden] style.
FIX
[hidden] { display: none !important }

Bug · searching "module 2" matched every note

CAUSE
The words were matched one at a time, and "module" and "2" appear almost everywhere.
FIX
Match the whole phrase first, and fall back to separate words only when the phrase isn't found.

Bug · highlighted header text unreadable

CAUSE
Light title text on a peach highlight.
FIX
Mark text uses var(--ink) on screen. In print, highlights are hidden and the text keeps its own colour (color: inherit).

Bug · Backlog opened halfway down the page

CAUSE
The route pointed to an anchor (#naming-parts) inside the page.
FIX
Route to the bare file, .prog/index.html.

Bug · headless test browser kept the profile locked

CAUSE
Piping a test into | head killed the script with EPIPE, and the headless Brave it started kept running.
FIX
Find and stop it, then don't pipe test runners into head.
pgrep -af remote-debugging-port    # -a: full command line, -f: match against it
kill <pid>                         # only a process you started yourself

Bug · a public IP inside an archived PDF

CAUSE
An original PDF showed a server's public IP, which shouldn't be in the repo.
FIX
Redacted it with PyMuPDF in a scratch venv, replacing it with <instance-ip>, then amended the only commit and force-pushed.
for page in doc:                                     # doc = fitz.open("archive/….pdf")
    for r in page.search_for(ip):                    # every spot the text appears
        page.add_redact_annot(r, text="<instance-ip>")
    page.apply_redactions()                          # deletes the text, not just hides it
Gotcha · A force-push rewrites the branch, but GitHub can still serve the old commit to anyone who has its exact link. Keep private data out before the first push.

Best practices

Two palettes, kept apartNotes use only chalk-pastel.css, and the site frame uses only site-theme.css. No hex values anywhere else.
No build stepPlain files that open from disk and can be hosted anywhere unchanged. Generated data goes into script files.
Test headlessDrive headless Brave over CDP from small node scripts to check layout, search and highlighting.
Access ≠ permissionSetting up push access is not a request to push. Push, publish or force-push only when asked, every time.
Private stays localBacklog, research and records go in gitignored folders. Check git status before every commit.
Rules in one placeChange CLAUDE.md only on request, then update the guide HTML and PDF too.
