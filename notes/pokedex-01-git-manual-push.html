The big picture

ConceptThree places a file can be

Working folderyour files on disk
Index (staging).git/index — the next commit
HEADyour last commit
originGitHub's copy
Concept · git add moves folder → index · git commit seals index → HEAD · git push sends HEAD → origin. git status compares them: folder ≠ index = red “not staged”, index ≠ HEAD = green “to be committed”.

The push routine

Every pushLook before you touch

cd ~/Projects/pokedex    # go to the repo
git status               # what changed, what's staged
git remote -v            # which GitHub repo this folder talks to
git log --oneline -5     # last 5 commits, one line each

New repo onlyBrand-new repo

git init -b main               # start
git remote add origin <url>    # link GitHub
git push -u origin main        # 1st push

Check .gitignore first: node_modules/, dist/.

Existing repoYour case today

git pull --rebase    # sync first
git push             # then push

git remote -v already showed origin → skip the new-repo steps.

Every pushStage, commit, push

git add -A                                 # stage everything: modified, deleted, new
git status                                 # check: all green
git commit -m "Title" -m "Description."    # 1st -m = title, 2nd = body
git push                                   # HTTPS remote: username + access token
git status                                 # expect "up to date with 'origin/main'"

Starship prompt shorthand: » renamed · ! modified · ? untracked · ✘ deleted · + staged · ↑ ahead of GitHub (push me).

Commit messages

Shape of a good message ·
  • Title: one short line, sentence case, what changed, no full stop. Shown by git log --oneline.
  • Body: after a blank line — the what and why. Each extra -m = one more paragraph (no limit).
  • One change per commit is best practice; git add -A for “everything at once” is fine when it all belongs together.
git commit -m "Lore page board, cabin and Pokédex updates" -m "Lore content now sits on a padded board, …"  # today's commit

ConceptTrailers: Key: value lines in the last paragraph

TrailerMeaning
Co-Authored-By:Someone helped — GitHub shows both avatars
Signed-off-by:“I wrote it and may submit it” (Linux kernel style)
Reviewed-by / Tested-byCredit checkers and testers
Closes: #12Auto-closes GitHub issue 12
git commit -s -m "Title"                         # -s adds Signed-off-by
git commit -m "Title" --trailer "Closes: #12"    # any trailer, no extra -m
git log -1 --format='%(trailers)'                # show only trailers

Inside .git/index (with xxd)

Concept · The staging area is a real binary file: a list of path → content hash, plus each file's stat info (size, timestamps, inode) so git status can skip re-reading unchanged files. File contents live in .git/objects, not here.
xxd .git/index | head -8             # first 128 bytes as hex
git ls-files --stage .gitignore      # Git's decoded view of one entry
git show :src/pokedex/pokedex.css    # ":" = the staged version of a file
OffsetBytes (your repo)Meaning

Reading an xxd row: left = byte position · middle = bytes in hex · right = same bytes as text (dots = unprintable).

Bugs hit & fixed

Bug · git rmove -v

CAUSE
A typo. Git suggests the closest real command (remote).
FIX
Run the suggested git remote -v.

Bug · xxd: command not found

CAUSE
xxd wasn't installed. zsh's helper searched pacman's file database: three packages provide it.
FIX
Picked tinyxxd (smallest). The default choice (1) was gvim — don't just hit Enter.

Bug · database file for 'chaotic-aur' does not exist

CAUSE
pacman's file lists had never been synced.
FIX
Sync them:
sudo pacman -Fy    # -F: file database, -y: refresh it

Bug · red 404s while installing

CAUSE
The mirrors had moved to a newer version than the local package list.
FIX
Do a full upgrade — never -Sy alone (partial upgrade):
sudo pacman -Syu    # -S: sync, -y: refresh lists, -u: upgrade everything
Gotcha ·
  • git commit -am skips untracked files — it would have missed the new pokedex.css. Use git add -A.
  • Unstaging a rename splits it into deleted + untracked; re-adding both rejoins it as renamed (98%).
  • HTTPS remote: GitHub wants a personal access token, not your password.
