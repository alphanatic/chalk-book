Sorting a list 0–9, a–z

HTML has no built-in sort. Two ways:

WayWhen
Write it sorted in the sourceThe list only changes by editing the file. No script; works from disk and in print
Sort on load with a scriptRows may arrive in any order and must always end up sorted
const byNatural = new Intl.Collator(undefined, { numeric: true, sensitivity: "base" }).compare;
const rows = [...table.querySelectorAll("tr")].slice(1);  // skip the header row
rows.sort((a, b) => byNatural(a.cells[0].textContent, b.cells[0].textContent))
    .forEach(r => r.parentNode.appendChild(r));  // moves each row to the end, in order
Plain text sortNatural sort (numeric: true)
1, 10, 2, L011, 2, 10, L01
Gotcha · Sorting the table alone leaves the cards below in the old order. Sort both, or sort neither and fix the source.

Bugs hit & fixed

Bug · zsh ate a separator line

CAUSE
echo ===== failed with (eval):1: ==== not found. In zsh a word starting with = expands to a command's path, like =ls → /usr/bin/ls.
FIX
Quote it, or use a separator that doesn't start with =.
echo '====='    # quoted: printed as-is

Bug · legacy items ignored by the filter

CAUSE
The filter hides elements by data-platform. The old items had none, so they showed under every filter.
FIX
Gave each legacy card and overview row a data-platform, plus rank and kind chips.

Bug · two items, one new name

CAUSE
The rename list mapped both C13 and C16 to L03. Duplicate ids break the overview links.
FIX
Asked instead of guessing: C13 → L02, C16 → L03. Later shortened to L1–L3.
